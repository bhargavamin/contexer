# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Commands

```bash
# Install dependencies
uv sync

# Run the server (stdio transport — for manual testing)
uv run python server.py

# Smoke-test the server responds to MCP initialize
echo '{"jsonrpc":"2.0","id":1,"method":"initialize","params":{"protocolVersion":"2024-11-05","capabilities":{},"clientInfo":{"name":"test","version":"0"}}}' | uv run python server.py
```

## Architecture

A small package (`contexer/`), intentionally minimal:

- **`contexer/server.py`** — MCP server entry point. Defines tools (`capture_user_constraint`, `update_context`, `approve_decision`, `review_pending`, `get_context`, `get_context_for_prompt`, `bootstrap_context`, `list_shareable`, `share_decision`, `update_global_context`, `get_global_context`) using `FastMCP`. Generates a `SESSION_ID` (UUID) at process start shared across all tool calls in a session. Delegates all logic to `store.py`. **Pending-review UX is non-blocking:** `update_context` capturing an AI-inferred constraint / L3 architecture decision returns a *"pending review — not yet trusted, does not block your work"* notice (never a "wait for the developer" prompt); the identified list with content is pulled on demand via `review_pending` (the in-session twin of `contexer review`), and SessionStart injects only a **count** (not per-decision content) to keep startup light. **`share_decision` is confirmed-by-default:** an outward push previews what would leave the machine (`confirm=false`, a pure local read, only when a team endpoint is configured) and requires `confirm=true` to send; a developer can opt out with `skip_confirm = true` in `config.toml`. When the developer hasn't named a decision, `list_shareable` returns an identified list to pick from, and `share_decision` accepts a comma-separated **multi-select** (`"id1,id2"`) so a whole selection previews + pushes in one call. The CLI mirror is `contexer share` with no args → a numbered interactive multi-select picker.
- **`contexer/store.py`** — All read/write and filtering logic. `_passes_filter` is the core gate: content is stored only if it is novel (token-overlap check — >70% overlap with existing decisions = duplicate). Storage is capped at `MAX_ENTRIES = 500` per repo. Display is separately capped: `_UNFILTERED_DISPLAY = 10` for overview calls, `_FILTERED_DISPLAY = 25` for query/type-filtered calls. Bootstrap is insight-aware: `_detect_insight(repo_path)` infers the user's familiarity (`high`/`medium`/`low` + decisive flag) from git signals — commit authorship by `user.email`, first-commit authorship, fresh-clone reflog entries. Detection order is load-bearing: the empty-email check must run before any `--author` query (an empty author pattern matches every commit). Detection is TTL-cached by `_cached_insight` (24h, `~/.contexer/.insight_<slug>`, fail-soft), validated on read against the current `user.email` + `HEAD` — a cache hit costs 2 git subprocesses instead of ~6, and a changed identity or re-cloned/rewound repo invalidates immediately rather than after the TTL; `_detect_insight` stays pure for tests. `bootstrap_scan(repo_path, insight, mined=None)` filters gap questions by each gap's `min_insight` AND suppresses questions the miner already measured (tests-in-scope, CI, team conventions when ≥3 conventions mined); empty `insight` auto-detects. **`bootstrap_apply(repo_path, session_id, insight)` is the self-storing bootstrap** (what the `bootstrap_context` tool runs by default, `apply=True`): scan + `miner.mine_conventions` + persist under one store lock with one save — exactly ONE consolidated `"Stack: ..."` architecture entry (never ~15 per-fact entries), each mined convention as its own decision tier-gated by evidence (≥90% dominance → born `approved` via `created_by="scan"`; 60–89% → `pending_approval` — deliberately NOT `suggested`, which would inject at session start and never surface in `review_pending` — arming the `.pending_review` nudge). Idempotent: skip-don't-bump `_find_match` dedup, so re-calls store 0 and never touch `occurrence_count`. The model's only remaining bootstrap jobs are reporting the returned `stored`/`pending` counts and asking the residual author-only gap questions. Non-decisive detection makes the offer ask the user directly. **The offer is a numbered menu of at most FOUR options in every variant**, and the injected block tells the model to render it as one interactive multiple-choice question where the host has that tool (Claude Code: `AskUserQuestion`), else as the numbered text list — a number and its own row's keyword mean the same thing, but **which** keyword sits at a given number is variant-dependent (`2` is `full` in the high/ambiguous menus and `quick` in the low one), so never hardcode a number→mode map. Four is the picker's option cap (plus its own free-text "Other"), which is why `some` has no row in the ambiguous variant: it stays a documented typed reply mapping to `insight='medium'`, and `scan` absorbs its "didn't build it" meaning — **so in the ambiguous variant `scan` routes to `insight='medium'`, not `'low'`**: `'low'` returns only the goal gap, silently dropping the purpose question (`min_insight='medium'`) for the one user class `some` existed to serve; the low-decisive variant, where the evidence says no commits, still routes `scan → 'low'`. For the same reason the affirmative is variant-relative: a bare "yes" means **option 1 of the variant on screen** (`quick` in high, `scan` in low), never a fixed keyword, since a blanket `yes → quick` would start the author interview precisely where the evidence says the user cannot answer — and in the **ambiguous** variant it resolves to nothing at all, because that question is "how well do you know this repo?" whose option 1 asserts authorship a bare "yes" never claims; there the model must ask which option instead of inferring. The offer rows are also emitted **unquoted**: the block used to be wrapped in script quotes, invisible in verbatim text mode but rendered into the picker's own labels (`not now"`). Gap questions are asked the same way, but that ask shape lives in **`store.GAP_ASK_GUIDE`**, attached by `server.bootstrap_context` as a `how_to_ask` field **only when the result carries gaps** — never inlined into `_build_bootstrap_context`, which is injected at every context-less session start, again at the first `UserPromptSubmit`, and post-compact, including the skip and STEP 0 paths where no gap is ever asked (~470 tokens per injection, ×2-3 per first turn). `/bootstrap` and the docs point at that field instead of restating it, so the rule cannot drift across copies — it had already drifted in `bootstrap_command.md` within one commit. The shape itself: ONE question at a time, never batched (batching would skip the between-answer re-evaluation that drops tests/CI/deploy gaps for a docs-only repo); last option = "Skip this one"; a "Correct" option (description = the gap's `assumption`) ONLY when that assumption actually answers the gap's question — the goal gap's assumption is the repo's inferred purpose, so there it is dropped and the question asked openly; up to two candidate options in between ONLY when the `hint` names distinct candidate answers (half the hints are one comma-list belonging to a single answer, or a restatement of the question); and the stored sentence must ANSWER THE QUESTION, never echo the assumption's wording. No host plumbing: the capability line is host-neutral text in `_build_bootstrap_context`, so a host without the tool simply falls through to the text list and a new adapter inherits both for free. **The offer fires at most once per session per repo**, gated by `~/.contexer/.bootstrap_offered_<slug>` (`_arm_offer` / `_offer_already_made`): skipping stores no decision, so the `if decisions` guard never trips and every later prompt — plus every `/compact` — used to rebuild the block and re-open the picker the developer had just dismissed, one modal per prompt. A non-resume, non-`compact` session start clears the flag (a genuinely new session offers again); `compact` deliberately does not, since it continues the session in which the developer already answered. The STEP 0 newcomer-answer path is NOT gated — it shows no menu, and gating it would swallow the answer. Fail-soft (a flag error degrades to the old always-offer behaviour) and swept by `_gc_stale_session_files` for repos never reopened. Known limitation: commit count is repo-wide, so a few commits in one corner of a monorepo read as insight into the whole repo. **Retrieval V1 (topic router).** `get_context_for_prompt(repo_path, prompt, session_id="")` (called by `claude.rationale` — Codex reuses it verbatim — and Gemini's `before_agent`) is BM25-backed by a disposable index sidecar (`STORE_DIR/.retrieval_index_<slug>.json`, indexing only `approved`/`suggested` decisions — `ignored`/`pending_approval` entries are excluded so a stale index can never advertise a topic `get_context` would refuse to return) written ONLY at the tail of `_save` (every writer already holds the store lock, so no extra locking) and read-only per prompt via `_read_retrieval_index` — a missing/corrupt/wrong-version index falls back verbatim to the pre-V1 keyword lookup (`_legacy_prompt_context`), never rebuilt inline. Ranking (`_bm25_rank`, k1=1.5 b=0.75) tokenizes the query with `_index_tokens` — the same tokenizer the index itself uses — and expands any query term absent from the corpus to every indexed token sharing it as a prefix (restoring legacy `\b`-prefix recall: `postgres` still matches a doc holding only `postgresql`); that plus `_derive_topics` (a fixed alias table: db/api/auth/frontend/deploy/testing/config/perf/security) and `_extract_artifacts` (file paths, dotted modules, `*Error`/`*Exception`, route-shaped strings — double-weighted in the query) drive an injection ladder: STRONG matches (relative threshold, capped at 3) render full decision content under `[Contexer: auto-fetched for this question]`; else WEAK topic overlap returns a short pointer (`[Contexer] Related stored decisions: ...`) and logs a `pointer` event; else — for rationale/project prompts only — an overview fallback (`get_context()`, no query) and then a global-store lookup; anything else (a topic-word-only or artifact-only task prompt with no strong or weak hit) stays silent by design, matching the pinned `test_benchmark.py` misses. `get_context` itself retries a literal-miss query that names a bare topic (e.g. `query='db'`, exactly what a pointer suggests calling) against that topic's alias tokens, so the suggested follow-up actually returns the aliased decisions instead of nothing. A per-session working set (`working_set_ids`, `.ws_<slug>_<sid>.json`) skips re-injecting a decision already surfaced this session. `_local_session_start_payload` (via `session_start_payload`, which now takes an optional `session_id` threaded from the SessionStart hook's stdin) appends a size-gated standing topic map (`Stored decisions by topic: ...`) once a repo holds ≥20 decisions, and on a `compact` source with a session id re-injects the CONTENT of the session's most-recently-injected working-set decisions (capped at 10, active statuses only) under a `## Rehydrated working context` heading — the pre-compaction router state would otherwise be lost on replay. Compact-reload parity holds across all three hosts: Claude re-injects via `SessionStart(source="compact")`, Gemini's `before_agent` post-compression reload and Codex's post-compact entrypoint (`get_post_compact_context`) both thread the same `session_id` into `post_compact_payload`, which calls the identical `_rehydrate_working_set` helper — no host loses pre-compaction router state on replay. Every non-resume session start also runs a fail-soft GC sweep dropping working-set/log files older than 7 days. The retrieval log (`.retrieval_<slug>.jsonl`, tail-capped at 200 lines) records `pointer` events and, from the `get_context` MCP tool, a `followup` event when a query matches a still-fresh pointer's topic — a log-only usage signal, never a behavior change.
- **`contexer/miner.py`** — deterministic convention mining, stdlib only (`ast`/`tomllib`/`re`/`configparser`/`subprocess`). `mine_conventions(repo_path) -> list[dict]` (`{"content", "subtype": convention|pattern, "tier": high|medium}`) measures conventions with whole-repo evidence embedded in the sentence itself ("Functions use snake_case naming (98% of 412 functions across 37 files)"): config-encoded rules (ruff line-length/quotes, mypy strict, pytest coverage floor, .editorconfig, pre-commit hook ids via regex, prettier/eslint/tsconfig-jsonc, CI `run:` lines), AST source statistics (naming dominance, type-hint/docstring coverage, absolute-vs-relative imports, custom exception classes, bare-except absence), test conventions (layout, naming pattern, plain-assert vs unittest dominance, fixture count), and commit-message convention (Conventional Commits % over the last 100). Thresholds are the verification story: ≥90% dominance with ≥20 samples → tier high, 60–89% → medium, below either bar → not emitted (silence over noise); presence detectors need ≥3 occurrences. Caps: ≤400 .py files, ≤200KB/file, ≤2000 dirs; skips `_SKIP_DIRS` and ALL dot-directories (tool state like `.claude` worktrees would poison the statistics). Never raises; never emits `subtype="constraint"` (scan-sourced entries bypass the constraint→pending rule in `_classify_level`). A leaf module: imported by store.py, never imports it (own tiny `_git`). JS/TS/Go/Rust *source* stats are deliberately out of scope — their conventions are captured via configs, which is the verified path.
- **`contexer/redact.py`** — deterministic secret redaction, stdlib only (`re`). `scrub(text) -> (redacted_text, count)` (plus `scrub_text` / `count_secrets` convenience wrappers) replaces each detected secret with `[REDACTED:<kind>]`. **Balanced** detection: high-confidence provider token shapes (AWS `AKIA/ASIA`, GitHub `gh*_`/`github_pat_`, Slack `xox*`, Stripe `[sr]k_live_`, Google `AIza`, OpenAI/Anthropic `sk-`/`sk-ant-`, SendGrid, `npm_`, `pypi-`, Twilio `SK`), PEM private-key blocks, JWTs, `Bearer` tokens, and connection-string passwords, PLUS a keyword-gated generic catch-all (`password|secret|token|api_key|access_key|client_secret|private_key|auth …[:=] value`) that redacts the value only when it **looks secret-like** (`_looks_secretlike`: ≥6 chars AND not a plain lowercase word / hyphenated phrase) and **skips placeholder-ish values** (`<…>`, `***`, `env(…)`, `${…}`, empty). The prose gate is deliberate: without it the catch-all mauls ordinary decision text like `auth: required` or `token = short-lived` (known tradeoff: an all-lowercase passphrase reads as prose and is missed — provider patterns still catch real API keys, and not corrupting stored decisions wins). No entropy heuristic (rejected — would false-positive on SHAs/UUIDs/base64). **Idempotent** (the `[REDACTED]` placeholder never re-matches) and **never raises** (any failure degrades to best-effort). A leaf module: imported by `store.py` and `remote.py`, imports neither. **Redaction is EGRESS-ONLY by deliberate design** — capture is NOT scrubbed, so the local store stays a faithful, verbatim record of decisions (scrubbing local `0600` files buys little when the real secrets sit in `~/.aws`/`.env`, and a redactor that silently rewrites captured decisions would corrupt the product's core value). Secrets are removed only where a decision actually LEAVES the machine: **`remote._wire_args`** (the last-mile every push/batch/drain funnels through → the hard guarantee no secret reaches the remote MCP), plus **`store._share_projection`** (so the confirm-preview + durable outbox show exactly what will be sent), with `format_share_preview` surfacing a `(N secrets redacted before sending)` banner. Honors a `_redaction_enabled()` fail-soft toggle reading `config.redact_secrets` (default **True** — safety holds unconfigured; opt out with `redact_secrets = false`). The flag is resolved **once per operation** and threaded down, never re-read per element: `get_shareable`/`get_shareable_all`/`_share_projection` and `remote._wire_args` all take a `redact_on` param (None = resolve locally), the batch `apush_decisions` resolves it once for the whole batch, and `format_share_preview` resolves the profile once (governing both endpoint and redaction) so an explicitly-passed profile's `redact_secrets` is honored rather than a fresh global config read. `RemoteStore._redact_on()` likewise honors the `Profile` the store was built from (`from_profile`) — an explicit opt-in must not be lost to a global opt-out on disk — falling back to the global config only for a profile-less (directly-constructed) store. The generic keyword catch-all redacts a **quoted** value as a whole span (a quoted passphrase with spaces is fully removed, not just its first word), and `Bearer` matching is case-insensitive.
- **`contexer/adapters/`** — one module per AI-assistant target. `base.py` holds shared config-file helpers (`_load`/`_save`/marker checks). **Marker-matching has two variants and picking the wrong one fails silently:** `_in_groups` matches against `str(hook_dict)` (the dict's *repr*, so it sees command + statusMessage + matcher at once) — but a repr escapes quotes, and every real hook command is `py -c "..."`, i.e. contains a double quote, which forces repr to `'`-delimit and rewrite an inner `'codex'` as `\'codex\'`. A gate keyed on a quoted marker therefore never matches, never recognizes the hook it just installed, and re-fires on every install forever (this was live in `codex.py`'s team-poll gate: pure churn, since the correct hook was re-added each time, but no Codex install was idempotent). Use `_in_commands` — raw `command` match, quote-safe — for **any marker containing a quote**. The trap is that a marker with single quotes alone *appears* to work, because repr leaves those untouched. `claude.py`, `cursor.py`, `codex.py`, and `gemini.py` each own that tool's MCP registration, hook wiring, install/uninstall/status, and provider-specific hook output. `__init__.py` is the registry (`detect()` / `select()`). Gemini stores MCP and hook configuration together in `~/.gemini/settings.json`; it uses `SessionStart`, `BeforeAgent`, `AfterTool(write_file|replace)`, `PreCompress`, and `SessionEnd`. Because `PreCompress` is asynchronous and Gemini has no `PostCompress`, `gemini.py` sets flags and re-injects stored context at the next `BeforeAgent` event.
- **`contexer/memory_sync.py`** — imports Claude Code's memory-tool facts (`~/.claude/projects/<slug>/memory/*.md`) into the store, so decisions a session persisted to the file-based memory tool (instead of calling `update_context`) still reach Contexer. This is a *coexistence* path, not a competitor for capture: rather than fight an authority contest hook-injected reminders always lose against another tool's system-prompt memory workflow, Contexer becomes a deterministic sync target. No model in the loop — parses each fact's YAML frontmatter (`description`/`type`/`originSessionId`) + body, splits multi-section docs on `##` headings into one entry each (never a raw blob), assigns a subtype by keyword rules (ordered `convention` > `constraint` > `pattern` > `architecture`, with a frontmatter-`type` backstop — `feedback`→convention, `project`→architecture — and an architecture default, so *every* import is queryable via `get_context(entry_type=...)`), and upserts the whole dir in one load+save via `store.upsert_memory_batch`, keyed on a stable `memory_key` (source file + `##` section; repeated headings are disambiguated so they don't collide) so a fact reworded on disk updates its entry *in place* rather than silently dropping the edit (<30% change) or accumulating a near-duplicate (>30% change). First-time creation still passes the >70% novelty filter, so a memory fact that merely restates an existing decision is recorded as a recurrence, not double-stored across the two systems. Provenance: `session_id` = the fact's `originSessionId`. Fail-soft per file — a malformed memory file is skipped, never raised. The module is neutral (takes a dir path); `adapters/claude.py` owns the Claude-specific `_memory_dir(repo_path)` slug derivation (`re.sub(r"[^a-zA-Z0-9]", "-", repo_path)` — the one fragile coupling point, marked in code: if Claude Code changes its project-dir encoding, sync fails *safe* (finds nothing, never wrong data) but can go quietly dead) and `sync_memory(repo_path)`, which skips the whole import when a content fingerprint (`~/.contexer/.memory_synced_<slug>`) is unchanged.
- **`contexer/cli.py`** — the `contexer` console script: bare invocation runs the MCP server; subcommands `install [--target claude|cursor|codex|gemini|all]` / `uninstall [--purge]` / `reinstall` / `status` / `version` / `help` manage tool configs. `install` auto-detects present tools (`~/.claude` → Claude Code, `~/.cursor` → Cursor, `~/.codex` → Codex, `~/.gemini` → Gemini CLI) and falls back to Claude Code when none is detected; `--target` overrides.
- **`server.py`** (repo root) — back-compat shim importing `contexer.server`; keeps `uv run python server.py` working.
- **`requirements.txt`** — Kept for reference; `pyproject.toml` is the authoritative dependency spec managed by `uv`.

## Storage

Context is stored at `~/.contexer/<repo_slug>.json` - one file per repo, plus `_global.json` for cross-repo decisions. The slug is the repo path with non-alphanumeric characters replaced by underscores. Each file holds a flat list of entries. Writes are atomic (unique temp file + `os.replace`, mode 0o600) so readers never see a torn file; corrupt files are read as empty rather than crashing.

### Decision / Revision model (Git-like: storage preserves history, replay = current)

A decision is the logical engineering decision; a **revision** is one immutable version of it. Storage preserves every revision forever; replay exposes only the current approved one (like Git keeping every commit but cloning HEAD). This separation is what lets engineering history accumulate without ever growing the prompt or letting stale/pending values leak into a session.

The model is **embedded**, not normalized into a second collection: each decision entry owns its revisions inline (`revisions[]`) with an explicit `current_revision_id` pointer. This is the correct serialization for strict 1-to-many ownership (a revision belongs to exactly one decision, is never shared, never queried independently) and keeps the flat-list-per-repo storage and atomic whole-file write intact. The heavy query-side concerns (timeline, diff, audit, analytics, team approval, shared semantic search) live **upstream** in the remote teams MCP that decisions forward to (`push_decision`) - this OSS local store is a capture client + cache + outbox, so duplicating a relational/vector engine locally would be wasted. The embedded JSON maps 1:1 onto upstream `decisions` + `revisions` (+ a future `revision_embeddings` index) tables when that day comes, so no schema migration is needed to add those.

**Decision entry** carries: `id` (= decision_id), `type` (`task` | `decision`), `subtype` (`architecture` | `constraint` | `pattern` | `convention` - maps to the upstream 3-value `type` enum, with `pattern`→`architecture` on forward), `status` (`approved` | `suggested` | `pending_approval` | `ignored`), `current_revision_id` (the active revision - precedence is the pointer, **never** timestamps), `session_id`, `session_ids` (all sessions that have seen it), `timestamp` (Created At - immutable), `updated_at` (bumped when the current revision changes), `occurrence_count`, `created_by`, `revisions[]` (canonical list of all revisions incl. current), and optionally `proposed_revision` (a pending Suggested Update - never replayed until approved) and `memory_key`. The decision also keeps `content` / `revision` (current `version_number`) / `confidence` / `confidence_factors` as a **synced HEAD-cache** of the current revision (`_sync_decision_cache`) so the many read sites stay O(1); the revisions are the source of truth, the cache is rewritten from them on every change.

**Revision object** (`_new_revision`): `revision_id`, `decision_id`, `version_number` (1-based), `content`, `confidence_score`, `evidence` (factor list), `created_at`, `approved_at`, `source` (provenance: `ai` | `human` | `scan` | `bootstrap` | `memory`). Revisions are immutable once superseded (the new-decision pre-approval edit amends v1 in place, since there is no prior version to preserve yet).

**Accessors / lifecycle:** `_current_revision(entry)` / `_current_content(entry)` resolve the pointer (fallback: last revision); `_append_revision(entry, content, source, approved_at)` creates the next version, advances `current_revision_id`, snapshots confidence onto the revision, and resyncs the cache; this is the single path used by trivial in-place updates, `_promote_proposal` (approve a Suggested Update), and memory-sync changes. Approving a brand-new `pending_approval` decision blesses revision 1 in place (no new version). **Migration is transparent and idempotent** (`_migrate_decision`, run from `_load`): a legacy entry (old `content`/`revision` head + historical-only `revisions[]` snapshots) is rebuilt into full revision objects + a `current_revision_id` on first load; persisted on next save; fail-safe (a corrupt file still reads as empty).

**Which repo a tool call targets** is resolved by `store._resolve_repo(repo_path)` with this precedence: (1) an explicit, sane `repo_path` argument; (2) `_SESSION_REPO` — the repo bound to the running MCP-server process, captured once at startup from its own cwd's git root via `server.main` → `set_session_repo(_git_root(os.getcwd()))`; (3) the shared `~/.contexer/.current_repo` pointer as a last resort. The per-process binding (2) exists because `.current_repo` is a single global file every assistant hook overwrites — a different tool or session could clobber it and send decisions to the wrong store file. `_is_sane_repo` rejects the home dir and tool config dirs (`~/.claude`, `~/.cursor`, `~/.codex`, `~/.gemini`, `~/.contexer`, `~/.config`) on every read and write, so a poisoned pointer can never select a config-dir store file (it also rejects the filesystem root). **Hooks additionally fall back to their own cwd** (`store._hook_cwd_repo`, applied in `session_start_payload`, `bootstrap_prompt_payload`, and the per-prompt Claude entrypoints): hosts run hooks with cwd = the project directory, and non-git projects are first-class stores keyed by absolute path, so an empty git-root from the hook's shell must not erase the session's identity - the 0.16.1 bug was SessionStart claiming "no context stored" in a non-git dir whose store existed, while the MCP tools (explicit `repo_path`) found it fine. The fallback is `_is_sane_repo`-guarded (a session opened in the home dir keeps the normal chain) and is deliberately NOT the retired `|| pwd` shell fallback: the shared pointer is only written from `session_start_payload` after the same sanity check, mirroring the git-repo case. `_resolve_repo` itself is unchanged - adding a cwd fallback there would misresolve for MCP servers whose cwd is not the project (Cursor launches its server outside the workspace).

## MCP integration

`contexer install` registers the server in `~/.claude.json` under `mcpServers`, pointing at the installed console script:

```json
{
  "contexer": {
    "type": "stdio",
    "command": "/Users/<you>/.local/bin/contexer"
  }
}
```

(A from-source dev install via `scripts/install.sh` wires `uv run --directory <clone> python server.py` instead.)

For Cursor, the equivalents are `~/.cursor/mcp.json` (MCP server registration) and `~/.cursor/hooks.json` (hook wiring), managed by `contexer/adapters/cursor.py`. The MCP server entry in `mcp.json` uses the same `contexer` command; hooks use Cursor's `sessionStart` and `beforeSubmitPrompt` event names.

For Codex, the MCP server is registered in `~/.codex/config.toml` (TOML) as `[mcp_servers.contexer]` with `command = "<contexer-bin>"`, and hooks live in `~/.codex/hooks.json` (JSON, same schema and event names as Claude's `settings.json` `hooks` block), both managed by `contexer/adapters/codex.py`. The `config.toml` edit is surgical text manipulation (validated with `tomllib` before writing) so only the contexer stanza is touched — `codex.py` adds no TOML-writer dependency.

For Gemini CLI, both the MCP server and managed hooks live in `~/.gemini/settings.json`, managed by `contexer/adapters/gemini.py`. Installation preserves unrelated keys, servers, and hook groups.

## Session behaviour (hooks)

`~/.claude/settings.json` wires up hooks globally (applies to every repo):

- **`SessionStart`** — first runs `claude.sync_memory` to import any memory-tool facts (crash-recovery net: catches facts whose previous session ended without a clean `SessionEnd` flush), then injects all *approved* conventions and constraints directly as project rules; injects a count pointer for deferred architecture/pattern decisions (fetched JIT via `get_context`); the same deferral applies to the synced **team** context section this hook appends via `store.session_start_payload` (`_team_section(..., defer_architecture=True)`) — a team-synced architecture decision renders as a count-only pointer alongside the local ones, not full content, with `get_context(entry_type="architecture")` returning both personal (`[scope=personal]`) and team (`[scope=team]`) architecture decisions in full on demand; deferral exempts a team architecture row that already collapses to the cheap `[scope=team] ratifies local decision <id>` one-liner (>= 0.7 token overlap with a stored local decision) — that row is already as light as the deferred-count pointer itself, so hiding it too would only throw away its ratification signal for zero token savings (`team_context.count_deferred_architecture` mirrors this exemption so the `status` suffix's `(M shown)` figure — see below — only subtracts rows genuinely hidden behind the pointer); injects a **count-only** pointer for decisions awaiting review (never their content — pulled on demand via `review_pending`); injects a bootstrap offer if no context exists. Resume-aware and compaction-aware via the `source` field read from hook stdin (`source_from_hook_stdin`): on `resume` with context, skips re-injection entirely (the conversation already contains it); on `resume` without context, injects transcript-mining instructions instead of the menu; on `compact` it takes the normal path and silently re-injects the full context (this is what reloads context after compaction — there is no separate `PostCompact` hook) (mine decisions from the visible conversation + store scan facts, all in the first turn — no human round-trip) and writes `~/.contexer/.resume_mining` so the UserPromptSubmit bootstrap fallback stays silent (the flag is consumed on first prompt; non-resume session starts clear stale flags).
- **`PostToolUse` (Write|Edit, silent flag)** - fires after every `Write` or `Edit` tool call. Touches `~/.contexer/.pending_capture` and returns `{}`. Completely silent - no UI output. This is the single deterministic "files changed this turn" signal; it is consumed by the next `UserPromptSubmit` (anchor) reminder.
- **`.pending_review` (deterministic mid-session nudge).** Unlike `.pending_capture` (written by a hook), the **per-repo** `~/.contexer/.pending_review_<slug>` flag is written by the **store**: `store.update_decision` touches it at the two spots that create a state awaiting the developer — a new `pending_approval` entry (gated on status) and a freshly-attached `proposed_revision` — after `_save`, inside the store lock (`store._touch_pending_review(repo_path)`). Per-repo (not global) so a pending decision in repo A never nudges a session in repo B. The per-prompt consumer is `store.pending_review_nudge(repo_path)`: it fires the count-less "offer to `review_pending`, then `approve_decision`" nudge **only** when this repo has a freshly-set flag AND still has decisions pending (`get_pending_decisions`) — so a flag left by an already-approved decision, or by another repo, never yields a false nudge — then clears the flag (fire-once; a new pending decision re-arms it). So decisions captured mid-session resurface at the next natural turn instead of waiting for the next SessionStart. Consumers per adapter: **Claude/Codex** call the Python entrypoint `claude.review_nudge` from a UserPromptSubmit hook (Python, not shell, so it can compute the slug and verify the store; Codex reuses `claude.review_nudge` verbatim and lists it in `_EVENT_MARKERS` since it has no sentinel); **Gemini** calls `store.pending_review_nudge` in `before_agent`, independent of the compaction-reload branch (a reload re-injects `get_context`, which *excludes* pending decisions, so the nudge must still fire); **Cursor** can't inject per-prompt context (`beforeSubmitPrompt` returns `{continue}`), so its reminder rides the always-apply `.mdc` rule body instead. `capture_user_constraint` deliberately does NOT arm this flag for its own `pending_approval` entries — its in-band `constraint_ack` notice (self-approval-proofed) already tells the model to surface the pending decision to the developer that same turn, so a second, deferred nudge would only double up.
- **No `Stop` hook.** An end-of-turn `Stop` hook that prompted the model (via `additionalContext`) to capture/review decisions was evaluated and removed: it added latency and tokens and depended on model behavior, while delivering nothing the deterministic `PostToolUse` flag + next-prompt anchor reminder doesn't already deliver at a non-interrupting moment. `claude.install`/`codex.install` actively strip a previously-installed Contexer `Stop` hook (matched on `.pending_capture`) while leaving any foreign `Stop` hook intact; the `Stop` marker stays in the uninstall tables for this cleanup. Decision *updates* are surfaced deterministically (the `proposed_revision` Pending Update + `contexer review`), not by mid-turn prompting.
- **`UserPromptSubmit` (anchor, command, every prompt)** — writes the git root to `~/.contexer/.current_repo`, but only when actually inside a git work tree (no `|| pwd` fallback — that could poison the pointer with a non-repo dir). Also checks for `~/.contexer/.pending_capture`: if present, deletes it and injects `additionalContext` reminding Claude to call `update_context` for decisions from the previous turn. Silent to the user — only Claude sees the injected context.
- **Bookkeeping writes are best-effort everywhere (#152).** `~/.contexer/.current_repo`, `.pending_capture`, `.pending_review`, and `.resume_mining` are *bookkeeping*, not context: the pointer is only the last resort in `_resolve_repo`, and the flags merely schedule a reminder. A sandboxed host can leave the workspace writable while `~/.contexer` is not (Codex's managed sandbox), and an unguarded write there used to raise `PermissionError` and abort `SessionStart` — Contexer injected nothing at all over a file it never needed in order to *read* context. So: every adapter anchors through the one fail-soft, sanity-checked `store.anchor_repo(repo)` helper (never a raw `write_text`); `_store_path`/`_global_path` treat their `STORE_DIR.mkdir` as best-effort so *readers* can't be crashed by an uncreatable store dir (writers still surface the failure at their own write); and the shell hooks guard both writes — `{ printf … > ~/.contexer/.current_repo; } 2>/dev/null || true` (braces matter: `cmd > f 2>/dev/null` opens the redirect *before* stderr is silenced, so a bare suffix still leaks the error) and `touch ~/.contexer/.pending_capture 2>/dev/null; echo '{}'` (`;` not `&&` — a failed touch must not swallow the hook's mandatory JSON output). `claude.install`/`codex.install` migrate the pre-#152 unguarded forms on the next `install`/`reinstall`, gated on `anchor_repo` in `ss_code` and on `claude._TOUCH_GUARD` / `claude._ANCHOR_GUARD` in the shell hooks. The invariant: **inability to write an optional bookkeeping file never prevents a hook from rendering context.**
- **`UserPromptSubmit` (bootstrap, command, once)** — calls `store.get_bootstrap_context_prompt` on the first prompt; injects the bootstrap offer if no context exists (fallback for when SessionStart is skipped).
- **`UserPromptSubmit` (constraint, command, every prompt)** — calls `claude.capture_constraint` with the prompt text. Detects prescriptive directives (`always X`, `never Y`, `from now on Z`) and stores them as `decision` entries automatically — no Claude involvement needed. Silent no-op for all other prompts. To avoid crowding the store, `_is_prescriptive_constraint` rejects anything that isn't a clean standalone directive: pasted blobs over `_MAX_DIRECTIVE_LEN` (300) chars, fenced code dumps, and tool/system-injected text (`<task-notification>`, `<system-reminder>`, Contexer's own injected context) — these merely *contain* directive words and are never genuine user rules. A clean standalone directive is stored **trusted** (`approved`) automatically; a directive carrying a conversation-local reference (`store._is_deictic`: this/these/those unless scoping the rule to `this repo`/`project`/`repository`/`codebase`; `it` unless in the self-resolving idiom `make it a <rule/...>`; non-trailing `here` — a trailing `here` means "in this repo" and stays trusted — bare `that` is excluded, relative/complementizer uses dominate) is stored `pending_approval` with an in-band ack (`store.constraint_ack`) that tells the model to notify the developer and explicitly forbids self-approval. A later clean restatement that matches (>70% token overlap) its own still-pending twin promotes it to `approved` in place rather than being silently dropped as a duplicate; entries the developer already `ignored` are excluded from that match so a re-typed rule lands fresh, not permanently blocked. When that overlap gate misses but the new directive is a containment match of a stored rule (>70% of the smaller side's tokens shared — a superset or subset restatement), it is routed onto that entry instead of accumulating: a superset of an approved rule becomes a `proposed_revision` (suggested update, developer-reviewed), a superset of its own pending twin promotes (clean) or amends in place (deictic), and a terse restatement of an approved rule records a recurrence — never a new overlapping entry; moderate lexical near-matches (0.25–0.7 overlap) are listed in the ack for developer-confirmed consolidation only.
- **`UserPromptSubmit` (rationale, command, every prompt)** — calls `claude.rationale` with the prompt text; auto-injects matching decisions when the prompt contains rationale keywords (why, reason, rationale, decided, etc.). Silent no-op for all other prompts. When it does inject, it also emits a user-facing `systemMessage` naming what was recalled ("Contexer: recalled N decision(s) (topics)" / "Contexer: pointed at related decisions (topics)"), with a token-savings estimate (injected estimate × `_SAVED_MULTIPLIER − 1`, benchmark-derived, nearest 10) appended only above `_COST_NOTE_TOKENS` — built from `store.get_context_for_prompt_with_meta`'s structured `{kind, count, topics}`, not scraped from the rendered text.
- **`UserPromptSubmit` (team poll, command, every prompt)** — calls `claude.team_poll(repo, raw, consumer)` (C7 delta-poll; `consumer` defaults to `"claude"`, Codex passes `"codex"` — Codex reuses this exact function). **Non-blocking by design: the prompt path never performs network I/O.** Mirrors the SessionStart deferral: a newly-approved `architecture`-typed row is never dumped into the "just approved" banner as full content — it's rolled into a single count-only line pointing at `get_context(entry_type="architecture")`, while non-architecture rows still render in full immediately. Delivery is a **per-repo sync log + per-consumer high-water mark** (replacing the old single `.team_pending_<slug>.json` file, which a single consumer would claim, starving any other session on the repo): `_sync` appends `{seq, ids}` to a `sync_log` inside the cache file whenever it merges new/updated team rows (`seq` is a stored monotonic counter, never wall-clock — deterministic, clock-skew-immune; the log is capped at the last 50 batches, oldest dropped — a consumer further behind than the cap just misses old *banners*, the rows stay reachable via `get_context`). Each consumer keeps its own marker `~/.contexer/.team_seen_<slug>_<consumer>.json`; `team_context.poll_nonblocking(repo, consumer)` returns the rows from every log batch with `seq >` that marker (deduped by id, current version resolved from the cache), advances the marker, and — at most once per 15s — spawns a detached refresher process (`python -m contexer.team_context <repo>`) whose synced batch surfaces on the *following* prompt. So a Claude and a Codex session on the same repo each receive every newly-synced batch exactly once, independently. A brand-new or corrupt marker initializes to the current log head (caught-up, injects nothing that once) rather than 0, because SessionStart already renders the existing backlog — the delta-poll must only surface batches logged *after* the session started. The throttle stamp is written *before* spawning so a crashing refresher can never cause a spawn storm; a leftover legacy pending file is deleted on first poll. All read paths are fail-soft (corrupt marker/log degrades to an empty injection, never raises). Trade-off (deliberate): one prompt of extra staleness vs. the synchronous poll, in exchange for a hard guarantee that a slow or hanging cloud (worst case previously: the full transport timeout, ~10s) can never stall prompt submission. The synchronous `team_context.poll()` remains for callers that want blocking semantics.
- **`PreCompact`** — runs `claude.sync_memory` to flush memory-tool facts before the context window collapses, then injects a systemMessage reminding Claude to call `update_context` for any unsaved decisions.
- **No `PostCompact` hook.** After compaction Claude Code fires `SessionStart` again with `source="compact"`, and that event silently re-injects the full context via `additionalContext` (the normal `session_start_payload` path) — so post-compaction reload is already owned, seamlessly, exactly like a fresh session start. A `PostCompact` hook was tried and removed: `PostCompact` supports no `additionalContext` and its `systemMessage` is user-facing only (the model never sees it), so it reloaded nothing and merely dumped the entire stored context into the transcript as visible noise on every `/compact`. `claude.install` now actively strips a previously-installed Contexer `PostCompact` hook (matched on `get_post_compact_context` / the sentinel) while leaving any foreign `PostCompact` hook intact; the `PostCompact` markers stay in the uninstall table for this cleanup. (The neutral `store.post_compact_payload` / `get_post_compact_context` helpers are retained for the Codex adapter and Gemini's `BeforeAgent` re-injection, which do inject on their own event models.)
- **`SessionEnd`** — runs `claude.sync_memory` to flush memory-tool facts on clean exit. The earlier decision to reject `SessionEnd` hooks was about *capture that needs the model to act* (a `SessionEnd` hook can't make Claude call a tool); this is a deterministic file import that needs no model, so it is valid here. These three triggers (`SessionStart`, `PreCompact`, `SessionEnd`) are the memory-sync surface; the import itself is idempotent, so running it at several of them is cheap.
- **Legacy repo-settings cleanup (upgrade hygiene).** The pre-CLI from-source installer (June 2026) wrote hooks into the *repo's* `.claude/settings.json` — including an `mcp_tool` hook calling the since-removed `capture_context` tool ("Unknown tool: capture_context" on every prompt) and a dead-clone `uv run --directory` SessionStart hook (a second, contradictory "no context stored yet" startup message next to the real global one). Modern installs only manage `~/.claude/settings.json`, so upgrades used to leave those behind. `claude.clean_legacy_repo_settings(repo)` strips hook groups that are recognizably ours (`_LEGACY_REPO_HOOK_MARKERS` match or an `mcp_tool` hook targeting the `contexer` server) and preserves everything foreign; it is called from `sync_memory` (so a plain package upgrade self-heals each repo the user opens a session in — `sync_memory` is the one adapter entrypoint every already-installed SessionStart hook calls, no reinstall needed) and from `install`/`uninstall` for the cwd's git root. `install` also prunes the stale `mcp__contexer__capture_context` allow entry, retires the legacy unconditional every-prompt reminder echo from home settings, and warns (cannot fix — plugin caches belong to Claude Code) when an installed Contexer *plugin* still ships the removed `capture_context` hook, advising `claude plugin update contexer`. The same package-only-upgrade class exists for removed hook *entrypoints*: pre-#58 installs wired `claude.capture_task` (Claude home settings and Codex `hooks.json` — the identical command string) and `cursor.capture_task` hooks, which would raise `AttributeError` on every prompt once the package is upgraded. Those entrypoints therefore exist as **self-retiring no-op stubs**: being invoked is proof of a stale hook (nothing else ever calls them), so the stub returns the host's silent no-op AND removes its own hook group — `claude.capture_task` heals `~/.claude/settings.json` and delegates `~/.codex/hooks.json` to `codex.retire_capture_task` (each module edits only its own file); `cursor.capture_task` heals `~/.cursor/hooks.json`. This adds zero cost to healthy installs (no per-prompt config reads — the stub only runs when a stale hook fires, and after the first fire the hook is gone). Gemini needs no stub: its `capture_task` use was internal to `before_agent`, whose installed hook command never changed.

**During a session**, call `update_context` whenever you make a significant decision, establish a pattern, or document a constraint. This is mandatory — not optional. After you write or edit files, the next user prompt will inject a reminder via `additionalContext`, but you should call it proactively within the same turn, not wait for the next prompt.

Call `update_context` for any of these:
- A technology, library, or approach chosen over alternatives (subtype: `architecture`)
- A file structure, naming convention, or code organization pattern established (subtype: `pattern`)
- A rule stated by the user or inferred from their preferences: "always X", "never Y" (subtype: `constraint` or `convention`)
- A build, deploy, or tooling convention established (subtype: `convention`)
- Any decision that would surprise a future Claude session if it wasn't stored

Pass the full reasoning, not just the conclusion. Pass `subtype` so decisions are retrievable by type. The server's novelty filter discards duplicates silently, so err on the side of calling it.

**Retrieving context JIT**: call `get_context` **before reading files** for any question about architecture, design decisions, rationale, constraints, patterns, or conventions. Fall back to reading files only when context is missing or the question is about current code state (exact syntax, current values). Use `query` for keyword search or `entry_type` to retrieve a specific subtype: `get_context(entry_type="constraint")` returns only constraints (up to 25). Use `limit` to override the display cap. When results are truncated, the output includes a `"showing N of M"` note so you know more exist.

## Design constraints

- **Silent operation is essential.** Tools must not produce noise — `update_context` silently discards filtered content without logging. This governs *capture and filtering* noise specifically; it does not forbid every user-facing message. The one deliberate, developer-ratified exception is the rationale hook's recall notice (above) — a short, structured line naming what Contexer fetched, so retrieval is observable rather than spooky.
- **Secrets never egress (capture stays faithful).** `redact.py` scrubs only where a decision leaves the machine — `remote._wire_args` (the wire guarantee) and `store._share_projection` (preview/outbox parity), surfaced by the `(N secrets redacted before sending)` preview banner. Capture is deliberately **not** redacted: the local store is a verbatim record, and silently rewriting captured decisions would corrupt the product's core value (scrubbing `0600` local files also buys little against a reader who already has `~/.aws`/`.env`). Redaction is default-on (`config.redact_secrets`), deterministic, idempotent, and fail-soft (a config error keeps it ON). Do not add an outbound path that bypasses `_wire_args` without extending redaction to it.
- **No abstraction beyond what exists.** The module structure (`server.py` / `store.py` / `cli.py` / `adapters/`) is intentional. Do not add classes, config files, or layers unless the spec changes. Adding support for a new tool = one new module in `adapters/`; no other files change.
- **`update_context` is called by Claude Code, not the developer.** Claude Code nominates content; the server filters. The filtering criterion is novelty — >70% token overlap with any existing decision is rejected as a duplicate, not an LLM call.
- **Git hooks and CLI commits are out of scope.** The MCP tool call path is the only capture mechanism.
